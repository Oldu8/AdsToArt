# AdsToArt — План продукта (инфраструктура монетизации)

> Этот план охватывает лендинг, кабинет пользователя и интеграцию с расширением для поддержки платных слотов под кастомные сеты. Лендинг и кабинет будут собираться как отдельный проект. Документ — человекочитаемый роадмап для ревью и доработки.

---

## Концепция

- **Бесплатно:** 8 встроенных тем, аккаунт не нужен, работает из коробки.
- **Платные слоты:** пользователь покупает слоты ($5 / $8 / $10 за 1 / 2 / 3 слота). В каждом слоте — один кастомный сет, который он собирает сам через кабинет.
- **Кастомный сет:** пользователь загружает свои фото, обрезает и настраивает их под каждый размер рекламного блока, сохраняет сет. Расширение использует его вместо (или наравне с) встроенными темами.

---

## Ключевые решения

| Тема | Решение |
|---|---|
| Авторизация | Только Google OAuth — без email/пароля |
| Изображений в сете | Минимум 8 (по одному на соотношение), максимум 32 (4 варианта на соотношение) |
| Прайсинг на лендинге | Секция на главной странице, не отдельная страница |
| Синхронизация сетов в расширении | Ручная — пользователь нажимает кнопку "Sync Sets" в попапе |
| Состояние сета во время редактирования | Расширение показывает последнюю сохранённую версию до следующей синхронизации |

---

## Авторизация: Google OAuth

Поскольку это расширение для Chrome, у каждого пользователя уже есть Google-аккаунт. Google OAuth — естественный выбор.

**В расширении:**
- `chrome.identity.getAuthToken({ interactive: true })` — получает Google токен одним вызовом, без UI
- Токен отправляется на бэкенд, бэкенд верифицирует его через Google API, находит или создаёт пользователя по email
- Сессионный токен сохраняется в `chrome.storage.local`

**На лендинге и в кабинете:**
- Стандартная кнопка "Sign in with Google"
- Бэкенд обрабатывает OAuth callback, выдаёт сессионную куку или JWT

**Что это убирает:**
- Верификацию email
- Сброс пароля
- Форму регистрации
- Онбординг в один клик для пользователя

## Итерации

### Итерация 1 — Фундамент

**Цель:** бэкенд, Google-авторизация и платежи работают. UI кабинета ещё нет.

- [ ] Выбор стека (например Next.js + Supabase или Node + Postgres + Stripe)
- [ ] Схема БД: пользователи, слоты, сеты, изображения, платежи
- [ ] Google OAuth: бэкенд-эндпоинт принимает Google токен, верифицирует через Google API, возвращает сессию
- [ ] Интеграция Stripe: разовый платёж за 1/2/3 слота, webhook для зачисления слотов
- [ ] API: эндпоинты авторизации + эндпоинт статуса слотов (расширение будет его вызывать)
- [ ] Лендинг — главная страница: hero, как это работает, секция с ценами (1/2/3 слота), CTA на "Sign in with Google"

**Результат:** пользователь может войти через Google, оплатить слоты, бэкенд знает сколько слотов у него есть.

---

### Итерация 2 — Кабинет

**Цель:** пользователь может создавать и управлять кастомными сетами.

- [ ] Layout кабинета: боковая навигация, защита роутов Google-сессией
- [ ] Дашборд: список сетов (название, статус, номер слота), кнопки создать / редактировать / удалить
- [ ] Страница редактора сета:
  - Загрузка изображений (drag & drop)
  - Обрезка / настройка под каждое соотношение (8 соотношений: 1:1, 4:3, 6:5, 1:3, 2:1, 10:1, 8:1, default)
  - Для каждого соотношения — до 4 вариантов (минимум 1 обязателен для публикации)
  - Сохранить / опубликовать сет
- [ ] Страница персональной информации: отображение Google-аккаунта (email, аватар), инфо о подключённом аккаунте
- [ ] Страница платежей: текущие слоты, купить ещё, история покупок

**Результат:** пользователь со слотом может собрать кастомный сет и опубликовать его.

---

### Итерация 3 — Интеграция расширения

**Цель:** расширение авторизуется и использует кастомные сеты пользователя.

- [ ] Кнопка "Sign in with Google" в попапе расширения через `chrome.identity.getAuthToken()`
- [ ] При авторизации: отправить токен на бэкенд, сохранить сессионный токен в `chrome.storage.local`
- [ ] Кнопка "Sync Sets" в попапе: запрашивает опубликованные сеты пользователя через API, сохраняет в `chrome.storage.local`
- [ ] Обновление UI попапа: кастомные слоты отображаются наравне с 8 дефолтными темами после синхронизации
- [ ] Логика фолбэка: если сет отсутствует или API недоступен → использовать выбранную дефолтную тему
- [ ] Кнопка выхода в попапе расширения

**Результат:** сквозной флоу работает — купил слот → собрал сет в кабинете → синкнул в расширении → расширение использует его.

---

### Итерация 4 — Расширение лендинга

**Цель:** SEO и инфраструктура для органического трафика.

- [ ] Блог (статический или на CMS, для репостов статей из LinkedIn/Twitter)
- [ ] Страница отзывов (парсинг из Chrome Web Store, отображение как testimonials)
- [ ] FAQ (секция или отдельная страница)
- [ ] Базовое SEO: meta-теги, Open Graph, sitemap, robots.txt
- [ ] Аналитика (например Plausible или GA4)

**Результат:** лендинг готов к органическому продвижению.

---

### Итерация 5 — Полировка и петля роста

**Цель:** снизить отток, улучшить конверсию.

- [ ] Приветственный email после первого входа (через Google email)
- [ ] Апсейл-подсказка в расширении (например "Добавь свои фото — от $5")
- [ ] Улучшить сайзинг изображений в расширении (починить "маленькая картинка с полосками по бокам")
- [ ] Редизайн попапа расширения
- [ ] Внутренний admin dashboard: количество пользователей, выручка, активные сеты

**Результат:** продукт готов к платному привлечению.

## Технический стек

| Слой | Выбор | Примечание |
|---|---|---|
| Фронтенд + SSR | Next.js | Лендинг, кабинет, серверный рендеринг |
| Серверная логика | Next.js Server Actions | Достаточно для CRUD; отдельный сервер не нужен |
| Stripe вебхуки | Next.js Route Handler | Внешние POST-запросы не работают через Server Actions |
| ORM | Drizzle | Типобезопасный, не привязан к конкретной БД — упрощает будущую миграцию |
| БД + хранилище файлов | Supabase | Postgres + Storage + встроенный Google OAuth (кастомный OAuth не нужен) |
| Платежи | Stripe | Разовые платежи за слоты |

**Путь миграции:** Supabase Postgres → собственный Postgres + Google Cloud. Drizzle делает это относительно безболезненным, так как не привязан к клиенту Supabase.
